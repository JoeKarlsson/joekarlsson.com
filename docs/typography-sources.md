# Typography sources and checkable rules

Knowledge base for a typography reviewer of joekarlsson.com (black background, hot-pink accents, Anton condensed all-caps display, Fraunces italic captions, sans body, long-form posts, a rotated "spine" word in the left rail).

Every source below was opened or found with WebFetch/WebSearch on 2026-11-16. All are third-party: independent typographers, designers, educators, books, publications and peer-reviewed research. No foundry product pages, no browser-vendor or platform docs (MDN, web.dev, Chrome, Apple HIG, Material), nothing from joekarlsson.com.

"Verified" notes how far each was checked: **read** = page text fetched; **excerpt** = the book itself was not readable, rules come from a fetched excerpt, digest or review; **record** = existence confirmed (publisher/catalog/DOI), used for context only.

## 2. Rules by topic

Rules are written to be checked against a page. Numbers in brackets are source numbers.

### 2.1 Measure (line length)

- **R1.** Body text: 45-75 characters per line, 66 ideal (Bringhurst) [3][25][32]. Butterick allows 45-90 [1]. Ruder: over 60 is hard to read [9]; Ruder via Baymard 50-60 [49]. Tschichold: 8-12 words [10]. Hobday: ~70, 60-80 fine [35]. Baymard's takeaway: 50-75, CSS ~70ch / 34em [49]. Cavazza: 60-70, `max-width: 60ch` [27].
- **R2.** Multi-column or narrow side text (captions, sidenotes, footnotes, rail text): 35-50 characters [3][32].
- **R3.** Set the measure in `em`/`ch` so it holds at any text size; px widths change character count when users resize [3][23].
- **R4.** Indented blocks (blockquotes, lists) must still land inside 45-90 [1].
- **Disagreement:** research finds longer lines (up to ~100 cpl) read as fast or faster on screen, but readers _prefer_ moderate lines; Dyson & Haselgrove found comprehension best at ~55 cpl; Bernard et al. found no speed difference and adults preferred ~65-75 cpl [50][51]. Treat 45-75 as the comfort/preference range, not a speed limit.

### 2.2 Body size

- **R5.** Web body text 15-25px [1]; at least 16px, the browser default [35][32]. Respect user settings: set root `font-size: 100%` [32][3].
- **R6.** Research: comprehension lowest at 10-12pt, best objective/subjective readability at 18pt+ [55]. Fluent reading spans x-heights of ~0.2°-2° of visual angle; below ~0.2° (critical print size) reading slows [53].
- **R7.** Prefer body faces with a larger x-height and open forms for screen [20]. Small text in dark mode suffers most (see 2.12) [44].

### 2.3 Leading (line-height)

- **R8.** Body line-height 120-145% of size [1]; web text 1.3 or more, 1.5 common [3]; ~140% benchmark [39]; 1.5 at 18px in [32]. Unitless values only [1][3].
- **R9.** Longer lines need more leading: add ~0.1 per 10 characters above 65 [32]; Tschichold: lines over 12 words need more lead [10]; Vignelli pairs size to column width (e.g. 10/11 up to 70mm columns, 12/13-14/16 up to 140mm) [7].
- **R10.** Reduce line-height as type gets larger; increase as it gets smaller [35]. Display lines may go below 1 (e.g. 0.85) only if ascenders and descenders do not collide [3]. All-caps display has no descenders, so tight leading is safer there.
- **R11.** Rello et al.: line spacing 0.8 hurt comprehension; 1.0-1.4 fine [55].
- **R12.** Dark backgrounds: one handbook raises paragraph line-height from 1.5 to 1.6 in dark mode [32] (single source; treat as a suggestion).

### 2.4 Paragraphs

- **R13.** Separate paragraphs by indent _or_ space, never both [1][3]. Indent: 1-4x the point size [1]; at least 1 en, line-height is a good value [3]. Space: 50-100% of body size (4-10pt in print) [1]; on a rhythm grid, one line-height [3][5][29].
- **R14.** First paragraph after a heading is flush (no indent) [3]. Tschichold insists on indents over space [10]; the web sources accept either.
- **R15.** Extra space above and below block quotations [3].
- **R16.** One space between sentences; no runs of spaces [1][3].

### 2.5 Vertical rhythm and baseline grid

- **R17.** Pick one base unit = body line-height; every margin, padding and heading line-height is a whole (or half) multiple of it [3][5][29][25].
- **R18.** Headings at other sizes get line-height = base ÷ size (e.g. 18/14 = 1.286) so they still occupy whole units; asymmetric heading margins are fine if top + bottom sum to whole units [3][5].
- **R19.** Images plus captions should total a multiple of the base line [3]; grid fields are a whole number of text lines deep; gaps between fields are 1, 2 or more whole lines, never half-lines [8].
- **R20.** Vignelli: intercolumn and intermodule space ideally one line of type [7].
- **R21.** Borders count toward height; compensate with padding so the block still fills whole units [5].
- Note: the web baseline sits mid-line (leading is split above and below), unlike print [3][29], so strict baseline alignment on the web is approximate.

### 2.6 Headings: spacing, size, case, levels

- **R22.** Space above a heading is clearly larger than space below, so the heading binds to the text it introduces (proximity) [29][46][32]. Latin's ratios: h1 3 lines above / 1 below; h2 2 / 1; h3 1 / 0 [29]. Vignelli: one line above and none below, or two above and one below [7]. Typography Handbook: 84px between sections vs 28px heading-to-text (3:1) [32].
- **R23.** Equal top and bottom margins make headings "float" between blocks: flag it [29][46].
- **R24.** Use no more than three heading levels; two is better [1].
- **R25.** Emphasize headings mostly with space; size steps can be small [1]. Vignelli: same size for heads and subheads, distinguished by bold [7].
- **R26.** Turn hyphenation off in headings; keep heading with next paragraph [1]. Use `text-wrap: balance` on headings and captions [6][32].
- **R27.** Don't center headings except titles/major section heads [1].
- **Disagreement:** Butterick says no all-caps headings [1] because his headings are often full sentences; caps are fine for headings under one line [1]. Anton all-caps display is within that allowance as long as headings stay short (see 2.9).

### 2.7 Hierarchy and scale

- **R28.** Compose with a scale, not arbitrary sizes [3][19][37]. Webtypography example: 36/24/18/16/14/12 [3]; Mortensen's classic scale (r = 2, 5 steps from 12pt): 6, 7, 8, 9, 10, 12, 14, 16, 18, 21, 24, 28, 32, 36, 42, 48, 55, 63, 73, 84, 96 [37].
- **R29.** Modular scale: base size × a ratio, optionally a second "important number" strand [19]. Smaller ratio on phones, larger on desktop: 1.125 → 1.25 [25]; 1.2 at 320px → 1.333 at 1500px [26].
- **R30.** Count distinct sizes on a page. Vignelli: one or two sizes, heads ~2x text (10pt text / 20pt heads) [7]. NN/g: no more than three sizes, at most two large elements [47]. Butterick: three heading levels max [1]. Flag pages with more than ~4-5 distinct text sizes.
- **R31.** Make hierarchy with weight, size and space before reaching for color; limit contrast variations to ~3 [47][22]. Large display against small text with generous space between is Vignelli's signature contrast [7].
- **R32.** Fewer illustration sizes = quieter page; keep images to a few fixed formats [8].

### 2.8 Tracking and letterspacing

- **R33.** All caps and small caps: add 5-12% (CSS 0.05-0.12em) [1]; Bringhurst 5-10% [3]; Pimp my Type starts at 0.1em and tunes by eye [30]; Hobday: start exaggerated and reduce [36]. Labels, nav, buttons and kickers in caps always get extra tracking [36][1].
- **R34.** Too much: when another letter would fit in a gap [1][30].
- **R35.** Lowercase body: no tracking change; remove tracking from large lowercase headlines [1][3]. General rule: tighten as size grows, loosen as size shrinks [35].
- **R36.** Light weights need more spacing, bold less; narrow bold faces can be set tighter [30]. **Applied to Anton:** a bold condensed caps face at display size needs little or no added tracking; small Anton labels (kickers, rail word at small sizes) need the full 5-12%. Check by eye with R34.
- **R37.** Use `em` for letter-spacing so it scales [3][30]. Keep kerning on [1].
- **R38.** Acronyms in running text: small caps with spacing (`font-variant-caps: all-small-caps`), only with true small caps [3]. No fake small caps [1].
- **R39.** Tschichold: capitals always letterspaced, balanced optically by eye between pairs [10].
- **Disagreement:** R33 (caps get more) and R35 (big type gets less) pull opposite ways for large display caps. Resolution most sources imply: tracking for caps is a small-size need [1][36]; at display sizes judge optically.

### 2.9 All-caps readability limits

- **R40.** All caps for less than one line only: headings, labels, captions, nav. Never paragraphs [1][48][21].
- **R41.** NN/g: avoid caps for passages of several words; caps beat lowercase only for single glanced words at very small sizes [48].
- **R42.** Research: caps were _more_ legible at small sizes (2x acuity) for both normal and low vision; the advantage vanishes at larger sizes [52]. Lowercase's advantage in running text is largely a practice effect, not word shape [42]. So the case against caps is about long passages and tone, not short display.
- **R43.** Condensed width costs ~11% in glance-reading time vs regular width [48]. Anton (condensed caps) is fine for short display; flag it for anything longer than a headline or any small size where it must be read quickly.

### 2.10 Typeface pairing and number of faces

- **R44.** Two typefaces usually plenty; three rarely; four almost never [1][20][35]. Vignelli works with a handful of faces in a whole career [7].
- **R45.** Give each face a consistent role (display, body, captions/margins) and change faces only at paragraph or element boundaries, never mid-paragraph [1].
- **R46.** Pair with clear, deliberate contrast; near-twins look like mistakes [20]. Butterick: serif/sans not required, and lower contrast can work [1]. Santa Maria: serif + sans is the easy route [20]. Don't pair two display faces [20].
- **R47.** Choose body face first for small-size sturdiness; save personality faces for display [20]. Build hierarchy inside a family (weight, italic, spaced caps) before adding a face [20].
- **R48.** Different readers read fastest in different fonts (~35% spread between a reader's fastest and slowest) and preference doesn't predict speed [56]: don't justify a body face on taste alone; test it.

### 2.11 Italics and emphasis

- **R49.** Bold or italic, never both; use sparingly [1].
- **R50.** Serif text: italic for gentle emphasis; sans text: prefer bold, since most sans italics barely differ [1].
- **R51.** Italic serif for captions/notes is a role change, not emphasis; keep it consistent (R45) and don't italicize again inside it except for titles.
- **R52.** Display weights (black/ultra) are for large headlines only [1].
- **R53.** Italicize uncommon foreign words; leave adjacent punctuation roman unless it collides [1].

### 2.12 Dark backgrounds, contrast and weight

- **R54.** Research favors dark-on-light (positive polarity) for normal vision, especially at small sizes and at night; dark mode helps some low-vision readers (cloudy media) [44][54]. A dark default is a stylistic choice that costs some legibility, so compensate with size and spacing.
- **R55.** Avoid pure #000 backgrounds and pure #fff text; use tinted near-black and off-white [34][35][28][57][39]. Typography Handbook aims for about 10:1 in dark mode, not maximum contrast [32]. Hobday: tint neutrals toward the palette, under ~5% saturation [35].
- **R56.** Halation: light text on black blurs or glows for many readers (astigmatism); automated contrast checkers won't catch it [57][28].
- **R57.** Avoid thin weights and hairline serifs on dark grounds [28][48].
- **R58.** Light-on-dark text tends to look tighter: open tracking slightly for small reversed text [16 via search excerpt].
- **Disagreement on weight:** Williams says reversed type looks smaller, use slightly heavier/larger [16]; halation arguments imply light text already looks bolder on screen. Practical check: compare the same paragraph at weight N and N-50 on the real background; pick the one whose counters stay open.
- **R59.** WCAG minimums as a floor: 4.5:1 body, 3:1 large text; AAA 7:1 [32][28]. Pink accent text must meet these on black.

### 2.13 Alignment, edges and optical correction

- **R60.** Default to flush-left, ragged-right; control the rag by eye [7][1]. Center only short titles and similar [1][7].
- **R61.** Every element should align with at least one other for a reason [35]; text, images and captions share the same grid edges [8][9].
- **R62.** Align optically when a shape's visual center differs from its geometric center [35]. Round and pointed letters overshoot the baseline and cap height to look equal; trust the eye over the ruler [40][15].
- **R63.** Hanging punctuation: opening quotes and bullets sit outside the text edge so letters align [33][38]. CSS `hanging-punctuation` has limited support; fallback is a tuned negative `text-indent` (~-0.5em) and `list-style-position: outside` [33].
- **R64.** Large display type: a letter's side bearing pushes its stem in from the edge; at display sizes the visible edge, not the box edge, should align with the body text edge (implied by [35][40]; no fetched source gives a number). Check: the left stem of a big Anton heading should line up with the left edge of the paragraph below.
- **R65.** Outer padding of a container ≥ inner gaps [35]. Measure spacing between the visible edges of high-contrast things (ink, not boxes) [35].

### 2.14 Captions and images

- **R66.** Captions sit below their image [8], flush with the image's left edge when body text is flush-left; center only on centered pages [16].
- **R67.** Caption width no wider than the image; measure 35-50 characters [32][3].
- **R68.** Image + caption height lands on whole rhythm units [3][8].
- **R69.** Captions get `text-wrap: balance` [6][32].

### 2.15 Rotated and vertical type (the spine word)

- **R70.** Reading direction: ISO 6357 makes descending (top-to-bottom, rotated 90° clockwise) the standard for Latin spine titles; ascending is "not standard" (but common in continental Europe) [ISO 6357]. Hobday says bottom-to-top _looks_ easier to read [36]. **Disagreement:** pick one direction and use it site-wide.
- **R71.** Vertical titles are decorative: fine where readers don't need to read them closely; never put essential navigation only in rotated text [36].
- **R72.** Prefer `writing-mode: vertical-rl` (keeps the text in layout flow, sized by its content) over `transform: rotate()`; add `rotate(180deg)` only to flip to bottom-to-top [24].
- **R73.** Rotated caps follow the caps tracking rules (R33-R36): tracking runs along the vertical axis.
- **R74.** Frame fit (derived; no source gives a rotated-type-specific rule): apply optical alignment [35][40] so the visible cap height of the rotated word has equal space on both long sides of its rail; measure from ink, not the line box, because the line box adds leading on one side. Its start and end should align with something on the grid (R61), e.g. the top of the masthead or the first text line.

### 2.16 Widows, orphans and rag

- **R75.** On the web the common fault is a single word alone on a paragraph's last line; fix with `text-wrap: pretty` on body or a non-breaking space [6][1][32].
- **R76.** `text-wrap: balance` for headings and captions only (spec limits it to a few lines); it isn't widow control for body text [6].
- **R77.** Hyphenation: leave at least 2 letters before and 3 after a break; no more than 3 consecutive hyphenated lines [3]. No hyphenation in headings [1]. Justified text must be hyphenated [1].
- **R78.** Don't fix rags with hard line breaks [1].

### 2.17 Numerals, quotes, dashes, symbols

- **R79.** Lining (titling) figures with caps; oldstyle (text) figures in running lowercase text if the font has them [3]. Use tabular figures in tables (implied by figure-width rule in [31]).
- **R80.** Curly quotes and apostrophes; straight marks only for feet/inches (primes) [1][31].
- **R81.** Hyphen for compounds, en dash for ranges (unspaced, "1880-1912" style with an en dash), em dash for breaks; never double hyphens [1][31]. Site style bans em dashes, so this rule reduces to: ranges use en dashes, not hyphens.
- **R82.** Real ellipsis character; one exclamation point per long document [1][31]. Non-breaking space after section marks and in short numeric expressions [1][3].
- **R83.** Letterspace long digit strings (phone numbers, serials) [3].

### 2.18 Responsive and fluid type

- **R84.** Interpolate sizes between a small-screen and large-screen scale instead of jumping at breakpoints [25][26]. Cap growth: a fixed max above the largest viewport [25].
- **R85.** Always declare a fixed fallback size before fluid values [25].
- **R86.** Grids start from content (comfortable measure), set the smallest and largest states first, and add breakpoints where relationships break [23]. Keep body text readable while display elements scale [23].
- **R87.** Phones are read closer: slightly smaller type, tighter leading and gutters than tablets [39]; but never below R5.
- **R88.** Groupings set by proximity can break when layouts stack on phones; recheck heading spacing (R22) at phone width [46].

### 2.19 Whitespace

- **R89.** Whitespace separates unrelated items and binds related ones [46][22]. "White space provides the silence"; a page crowded with many sizes is the failure case [7].
- **R90.** Avoid two hard dividers (rule, background change, container edge) next to each other [35].
